# 开发：离线判据台与真图标重放

取色这条链的判据全是数字，而数字**不能靠推演定**。仓库里 `_harness/`（被 `.gitignore` 的
`/_*/` 挡住，不入库）是一台纯 JVM 的判据台：手写一组 `android.graphics` 桩，把**仓里那份真
`MonochromeMask.kt`** 连驱动一起喂给 kotlinc，跑的是同一份代码而不是副本。

```sh
cd _harness && sh build.sh
sh regress.sh                        # 一条命令跑完整套回归：任何一项比基线差就**非零退出**
EDGES=96,192,384,768 sh regress.sh   # 全扫：同一批真图在四档边长上各跑一遍，顺带报"随边长漂移"
node _regress.cjs --update           # 认账，把这一轮写成新基线
java -cp out;stubs_out;<stdlib> harness.SelfTestKt        # 合成性质
java -cp out;stubs_out;<stdlib> harness.MaskBenchKt --shot --inset corpus
java -cp out;stubs_out;<stdlib> harness.ReplayKt ../_dump.txt captured   # 重放真机抓回来的图标
```

- **`regress.sh`** —— 为什么要有它：2026-09-29 一天里翻出两处**测量装置自己的洞**，两个都是
  "跑了、印了、没人拦"。① 语料目录里混着判据台自己 `--shot` 写回去的 42 张 `*_preview.png`，
  而 `MaskBench` 抓目录下所有 `.png` —— 于是"155 张 A/B"里 42 行是**输出**，`淡` 报的 39 实际是 25、
  `可分块` 报的 84 实际是 46（差值方向没坏，坏的是绝对数，已全部重测）。② `ab.sh` 那道
  "两份字节码一样=这一轮没在比东西"的闸门**永远不会响**：它把同一份内容写成
  `MonochromeMask.old.kt` / `.new.kt` 两个文件名，class 里带 `Compiled from <文件名>`，md5 必然不同。
  现在两份同名分目录，实测内容相同就当场拒跑。**防假 A/B 的那道闸也得有人防它。**
  ⚠ **它先要"能跑"这件事也得有人防**：2026-10-02 换机后它从取依赖那一步就断了，而 `out/` 里
  还躺着昨天的 class。七个脚本（`build/ab/ab_pair/abrun/cand/prun/regress`）现在一律
  `. jdk.sh` 自己钉住 JDK 17+（`JAVA_HOME` → 本机已知的 JDK 目录 → 找不到就**硬失败，并写明
  "这一轮一张都没测"**），不再指望 PATH 上那个 `java`（这台机器上它是 1.8）。
  ⚠ **`框内随边长漂移` 那一栏现在会写"未测"**：只跑 384 一档时没有一张图被量过两次，`driftN`
  恒为 0，而 0 在判定表里长得和"一格都没漂"一模一样，基线却是全扫记的 14 —— 于是它每轮都以
  "持平/更好"放行（**基线里那个 0 就是这么被写进去过一次的**）。未测就印未测：不计退步、
  也不冒充更好，`--update` 时**沿用旧基线的数**，要更新它必须
  `EDGES=96,192,384,768 sh regress.sh --update`。阳性对照做过：临时补一份第二档边长的输出，
  这一栏立刻变回一个真数。
  ⚠ **全扫的读数怎么解释（2026-10-21 第一次真跑，四档 `全绿`）**：`换支账` 那 5 张**全部**落在
  `没算·forceRef（按设计）`，"算了但结果不同" **0 张** ⇒ 这一轮证明的是"边长带来的换支都是设计"，
  **不是"算法对边长不敏感"**；而底线就等于实测值（**余量 0**），所以以后任何一次**真**漂移会当场把第十闸变红。
  别把"全绿"读成后者。另：`框内随边长漂移>0.15` 与 `bench/reg/drift.tsv` 点名表是**同一批东西的两个写法**，
  不是两处独立证据；这些张数**数的是行，不是应用**。
  这台子对着 `bench/baseline.json` 比 12 项（113 张真图的 `淡/字均净中位/残盘/档数`、`MonoKt`
  三条单调性审计、兼容性台 PASS/GAP/FAIL、`框内` 随边长的漂移张数）。拿已知退步的那一轮喂它：
  `淡 35 vs 基线 25`、`字均净 216 vs 224` —— **当场红，退出码 1**。
  ⚠ 它只报**总量**，而"淡 +1"既可能是"一张真坏了"也可能是"边界上抖了一下" —— 点名靠
  `node _abdiff.cjs 96,192,384,768`：它把 `ab.sh` 两份字节码各跑一遍的 `bench/reg/{old,new}_<边长>.txt`
  逐张对齐，列出**新掉进淡的**与**新爬出淡的**是哪几张、各自的 `H/框内/顶占比` 怎么变的。
  今天这一轮就是靠它把"总量 +1"翻成"3 个应用丢底板 / 2 个应用修好"的。
  - ⚠ **2026-10-08 起它多两件事，都是被一次错判逼出来的**（见更新日志最上面那条 🔴）：
    ① 比**掩码形状指纹**（`浓度[...]` + ASCII 图），不再只比判据数字 —— 那一轮 62 张里有 10 张
      只是 `拦=` 那位诊断位变了，**按数字会报"变了 10 张"，按形状是 0 张**；
    ② 每张点名都带 **`〔已适配·透传，不上屏〕` / `〔未适配·会上屏〕` / `〔没抓过·不知道〕`**，
      开头一栏直接印"变了 N 张，其中**会上屏 X 张**"。依据 = 各抓取目录 `index.tsv` 的 `mono` 列。
      **以后"修好了 N 张"这句话，没有这一栏就不算数。**

- **`SelfTest`** —— 自己造图，一张只有一个变量，断的是**性质**不是像素：底必须归 0、渐变底的
  **两端**都要归 0、透明底的轮廓与抗锯齿不许动、被围住的镂空要出来、贴着边的另一半 logo
  不许被当镂空擦掉、柔光不许切成骨架、整张同色必须明确不成立、以及**尺寸不变性**
  （同一张图在 192/256/384 上结论不许漂 —— 他报的「时对时错」就是这一类没守住）。
  ⚠ **但这条性质只钉住合成图**：2026-09-29 全扫 113 张真图标，`框内` 在 96→768 之间漂过 0.15 的
  有 **31 张**、漂过 0.30 的 **22 张**，最狠的几张是**换了一支配法**（通讯录 @192 走 H2、
  `框内=0.18` 正确；@384 掉到 H3「空气当参照」、`框内=0.87` = 整张涂满）。机制是尺度错配：
  `outlineFamilies` 那道闸 `n*50 < boxArea` 拿**轮廓像素数**比**面积**，而轮廓按周长长 ——
  边长翻倍，面积×4、周长×2，比值自己掉一半。**性质没抓到它，因为性质是在自己造的图上测边长的。**
  - ⚠ **"把单位修对"这一条量过两次，结论相反 —— 两次都对，差别在语料。**
    2026-09-29 在 113 张上逐张看图是 **2 好 / 2 明确坏 / 1 wash**（好：通讯录、腾讯元宝；坏：Azure
    Authenticator 与橙盘线字，两张把底板丢了）→ **当时不收，是对的。**
    2026-09-30 用 `debug/CorpusCapture` 一轮抓来 122 张真机图标，才发现**老语料里"满幅圆盘"这一类
    一张都没有**（判据 `框内≥0.66 且只有一档`：0/113 vs 7/122 —— 圆盘外沿只连着画布上那 21% 的
    空气角，H1 从框角取不到底），重判成 **10 好 / 2 坏 / 1 wash**，另买到 `框内随边长漂移 28→18`
    与 ρ色 0.871→0.915 —— **这一档收了。** 坏的一侧两次是同一批（Azure、混元：盘整个没了），
    **变的一直只是好的一侧被新语料补上。** 逐张对照：`_harness/bench/cmp_sheet/`。
  - ⚠ 但**"换一档常数"仍然不许**：该收与该拒在 `n/(bw+bh)` 上交错（见下面那条真值表）。
    **收的是"单位对"，不是"这档调得准"** —— 要修 Azure / 混元那一类，得换一个不描述参照长什么样的
    证据（第六种），别回到这道门里挑数，也别再试第六个阈值。
  还有一条对着**公开参考值**核整数 Lab 表（⚠ 参考值有 D65 与 D50/ICC 两套，同一个
  `#00FF00` 的 b\* 是 83.2 与 71.4，混过一次，报出来是个假故障）。
- **`MaskBench --shot`** —— 真实图标 + 一张「原图 | 浅色主题 | 深色主题」预览 PNG
  （桌面拿 alpha 当不透明度上色，所以预览就是 `plate×(1-a)+ink×a`）。
- **`DeliverKt`（交付档数台，只量）** —— **不合并**地数交出去那张占了几格 α，用来验"刻面被压平"
  这条假设（结论：假设查无实据，见更新日志最上面那条）。两条**读数前先守住**的规矩：
  ① **默认原生尺寸**（`--edge=0`）—— `rec3u` 的 feimo/browndust2 源文件是 192×192，
  拉到 384 的插值会把多出来的中间值数成层次，**只便宜那两张**；
  ② 档数只数**源本来 α=255** 的那些格（`交实`），"全部墨"（`交墨`）另存一列供对照 ——
  后者会被反锯齿斜坡虚高（taptap `源1 → 交墨4`），拿它当层次就是上一版 `淡` 被柔光污染的复发。
  ⚠ `墨/实` 那一列超过 ~400% 的张数上 `交实` 是在几十个像素上算的，别信它（`icon533` = 11113%）。
- **`run.sh`** —— `sh _harness/run.sh harness.XxxKt <语料目录>`。为什么要它：直接敲 `java -cp out`
  会漏 `kotlin-stdlib`，报 `NoClassDefFoundError: kotlin/jvm/internal/Intrinsics`，
  而那句错**长得像"这一轮没测出东西"**，不像"启动器坏了"。ab/prun/cand 三套 classpath 各写一遍，
  第四套就该收进一个文件里。
- **`Replay`** —— 把 `MonoDump` 从真机带回来的 PNG 拼回去重跑。**这条是必需的，不是便利**：
  他报的那批应用发的是 adaptive **vector** XML 或 **webp**，JVM 这边一张都解不出来，
  没有重放就等于对着代理图调参。抓回来的样本在 `captured/`。
  - ⚠ **分组键必须是 (进程, dump#N, what)**：`dump#N` 每进程各自从 1 数起，而一份抓取日志里
    有 2~4 个进程（桌面重启前后各一段、SystemUI / 设置也在作用域里）。只按 (序号, what) 拼 =
    两个图标的分片混进同一个桶、每个片号取最后到的那片。实测一份日志少读 **2/3** 的证据，
    另有 7~10 组被拼成"谁也认不出的 PNG"。新日志每行带 `p=`，旧日志退回 logcat 前缀里的 pid。
  - **复放必须凑齐三个输入**：模型吃的是 `(合成图, 层底, under)`，`under`（背景层）没带回来时
    `盘刀/反相` 在台上**根本不响** —— translate 实测 `反相=0/0` vs 设备自报 `66385/3454`。
    `层底=`/`层=` 两位打在 BEGIN 注记里，`层=1` 而 under 缺席时复放会单独报一行（不许静默降级）。
- **`ObjKt`（平色饼计数）** —— 判据台里**唯一一条只看产品自己、不看外部答案**的质量闸：
  **源图本来有 ≥4 档亮度、交出去却塌到有效档数 Neff ≤2.5** 的图标数。**只数模型真会处理的那些**
  （语料带 `index.tsv` 时按 `mono` 列排除自带单色层的 —— 那批按硬规则一个像素都不碰，
  数进来等于给自己刷分，见上面那条更正）。当前 **10 / 174**（真机未适配 61 + 老语料 113）。
- **`TonalGateKt`（入场判据的定线台）** —— 直接调**仓里那一个** `MonochromeMask.tonalClass`，
  把它的三个判据数在语料上排开，并列出"阈值往下挪一格就会进来的那批"。
  为什么单独要一台：`TonalKt` 是我另算的一套量（逐像素 ΔL、全分辨率精确色），而阈值要钉在
  **上屏那一份实现**的数上 —— 两处算法差一点（降采样平均 vs 逐像素、L\* 真值 vs 0..255 标度），
  同一个数就是两个判据。事实上当时的两套数差得很远：逐像素纹理在 96/192/384/768 上是
  55/67/73/36，而固定 96 格上是 55/57/58/58 —— **拿前者定阈值就是一条会随边长换人的闸门。**
  规矩：**判据的数必须由将要跑它的那段代码量出来。**
  - ⚠ 前两版定义都是**没牙的**，靠阳性对照才抓出来：① 「交付里出现过几种浓度」—— 平色饼照样
    有几万个抗锯齿中间值，旧版新版都报 0；② 绝对 Neff（不看源）—— 把「双色 logo 正确交出一张
    实心剪影」也算成病，两个构建都判 40% 塌，且对已知有效的三刀几乎不敏感。
  - ⚠ **它不是缺陷清单，是漂移探测器**（抽查过，别误读那个绝对数）。当前 10 张里抽了 4 张看图：
    WPS 的 W、12306 的铁路徽记加「中国铁路」、高德的纸飞机、学习通的彗星 —— **全是正确输出**。
    它们被标记是因为**图形本来就是单色的**，源里那 4~6 档是盘、底与阴影；把盘正确去掉之后，
    剩下的墨当然是一档。所以「源有层次」不等于「层次属于图形」，这条判据补不上去 ——
    它**能可靠地量出塌得变多/变少**（同一批图换构建，数字从 72 掉到 10），
    但**不能**说"这 10 张是坏的"。当趋势线用，别当缺陷清单用。
  - **阳性对照**：拿三刀之前的源码（`ae41472^`）跑同一个探针报 **23 / 49**，现在 **6 / 4**；
    把旧版数字塞回 `flat.txt`，判分器报 `72 vs 基线 10`、退出码 1 —— 闸门会红，不是装饰。
  - ⚠ 做对照时**必须连探针一起重编译**：`out_old` 留着上一版 `ObjKt` 时，我一度以为
    「旧版 0、新版 24」= 修复把事情做坏了，其实是两个量具在比。

- **`audit.sh` —— 全量审计一条命令：抓 → 渲 → 分类点名 → 与上一轮逐张 diff。**
  为什么要有它：主人的原话是「你得把算法变得通用，不然每次又要一个一个报给你问题」。
  算法侧的通用今天量到底了（见「全量清点三类可见坏法」那条），但**"发现问题"这一步确实可以从他
  身上搬走** —— 抓全机图标不需要手（`CorpusCapture` 三条 adb）、分类点名不需要手、
  与上一轮比谁变好谁变坏也不需要手。跑法 `sh audit.sh`（`--no-capture` 用现有语料、
  `--dir=` 换语料），产出 `bench/montage/montage_0*.png`（一屏几十张的总表）+
  `bench/audit/audit_<时间>.json`（逐张快照，下一轮自动 diff 出"变好/变坏"两张名单）。
  - ⚠ **A/B 两类是代理判据，输出里跟着印了那句限定**：实心气泡 logo 的 `框内` 天然高、
    多笔画 logo 的 `cc` 天然大，所以名单是"值得看一眼"而不是"缺陷清单"。
    一台只报合计的机器会逼人把名单当答案，这条限定不写就会被忘掉。
  - ⚠ **设备掉线不是失败**：`adb get-state` 不通时退回现有语料继续跑，但**在明面上印
    "这一轮没有新抓"** —— 悄悄用旧语料跑出一轮新数，比不跑更坏。
  - 路径的坑也写进脚本了：git-bash 会把 `adb pull /sdcard/...` 改写成 `D:/Git/sdcard/...`，
    报"remote object 不存在"看着像应用没写文件；要 `MSYS_NO_PATHCONV=1` 加 `//sdcard/` 双斜杠。
  - **第一次跑就点出一件该盯的事**：在 `corpus_dev2`（**capture 通道**）上 `flatVote` 开火 21 行，
    而"抬"的量远大于 dump 通道 —— chrome 抹1686/**抬1953**、documentsui **抬2770**、
    globalspeed 抹3113/**抬1557**、翻译 **抬1624**。这些图标在可信通道（`rec3`）上大多是 0，
    所以**不能当缺陷读**；但它说明"抬"这一侧在别的输入分布上会大幅活动，
    正是这条审计线该长期盯着的东西。
  - **这条线自己漏了一整族，2026-10-04 补上（[D]）**：A/B/C 三把读的都是 `框内 / cc / 顶占比 /
    字均净`，而"往干净地板上刷一层 4% 的膜"这四样**一个都不动** —— icbc 那张改前抬 788、改后
    逐张 diff 报的是"变好 0 张、变坏 0 张"，机器对着一次真修好说了句"没变化"。
    所以加了第四把 **[D] `票 抬>抹`**（唯一读 `票=` 自己的名单），并把 `er`/`ra` 写进快照让
    diff 能逐张比加墨量。⚠ **上一轮快照没有这一栏时不能当 0 用** —— 那样每张有抬的图都会
    被报成"变坏"，那是 schema 变更造的假账；缺就明说缺，从下一轮起才有对照。
  - ⚠ **`--dir=` 曾经是个假参数**：文档写了、脚本没解析，`sh audit.sh --dir=corpus_dev2` 实际
    跑的是默认的 `corpus_audit/`；那个目录不存在时 MaskBench 拿到空目录，`set -e` 让人**一句话
    都没听到就退出**。现在参数按任意顺序认，语料目录不存在/为空会点名报出来再退。
- **`CorpusCapture`（adb 触发，不需要他的手）** —— 一轮把本机**全部**可启动应用的图标抓成 384² PNG，
  补上 `MonoDump` 那条路的两个先天限制（只能带回桌面恰好问到的那几张、必须等他重渲染）。跑法三条 adb：
  ```sh
  adb shell 'echo "edge=384" > /sdcard/Android/data/com.iamcanincan.opticon/files/corpus_request.txt
             chmod 666 /sdcard/Android/data/com.iamcanincan.opticon/files/corpus_request.txt'
  adb shell content query --uri content://com.iamcanincan.opticon.config   # 叫醒进程并认领
  adb pull /sdcard/Android/data/com.iamcanincan.opticon/files/corpus _harness/corpus_dev
  ```
  `chmod 666` 只在**要带参数**（`pkg=<子串>` 筛包）时才需要 —— adb 写进本应用目录的文件属主是 shell，
  本进程默认 `open` 不动它；不带参数那一轮照样跑，只是拿默认值。`corpus/` 必须让应用自己建
  （shell 先 `mkdir` 过就先 `rmdir`，否则整轮 EACCES 写不进去）。
